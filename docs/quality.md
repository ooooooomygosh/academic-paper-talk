# 内容与质量标准

完成的汇报应使听众回答以下问题：作者要解决什么、最接近的方法缺什么、核心观察是什么、一次实际运行如何发生、哪些证据最有说服力，以及结论成立的条件。

## 科学核对

- 方法输入、时点、模块接口、符号和训练／在线分支与原文对应。
- baseline 的信息、硬件、测量、能量与计算预算明确。
- 指标、分母、范围和定量结果可追溯到原文。
- 组合消融、跨场景验证和实测范围不被扩大解释。
- 论文结论、解释推断、教学示例和研究设想可以区分。

## 汇报可用性

- 总体流程先于模块细节，每张内部图有明确位置。
- 关键公式保留在正文并解释变量。
- 复杂过程有一次运行的示例或足够清楚的原图讲解。
- notes 是完整口播，与独立讲稿同步，来源在页脚或附录。
- 不以删掉必要方法来追求“简洁”。

## 最终文件检查

从实际最终 PPTX 渲染每一页。逐条查看箭头、原图边界、表格末行、字体符号、标题换行和页脚间距。结构检查工具不能识别科学错误、推理缺口和全部视觉问题。
