# 常见问题

## 安装完成却找不到 skill

确认安装输出指向当前 Codex 使用的 skills 目录。设置过 `CODEX_HOME` 时，默认目录会随之变化；也可以通过 `--skills-dir` 显式指定。重新打开会话后，用完整名称 `$artifact-template-academic-paper-talk` 调用。

## 提示已有同名 skill

安装器默认保留现有目录。先比较个人修改，再运行 `python3 scripts/install.py --force`。旧版会备份到 skills 目录同级的 `skill-backups/`；安装输出会显示备份位置。需要恢复时，保留当前版本，再将对应备份复制回原安装位置。

## 运行环境支持到哪里

安装和检查工具需要 Python 3.10+，只用标准库。本地在 macOS 验证，CI 在 Ubuntu 上测试 Python 3.10 和 3.12；Windows 尚未验证。生成 PPT 还需要当前 Codex 的 Presentations 能力及其运行库。其他 agent 可参考说明文件，完整生成链路尚未在其他平台验证。

## 只有 DOI 或摘要可以吗

可以以 DOI 或链接启动全文获取。若正文无法访问，需要提供全文 PDF 或可用来源。准确解释公式、实验和 baseline 需要正文，摘要不足以支撑完整精读汇报。

## 能控制页数、语言和模板吗

可以。例如“总共 10 页含封面”“15 分钟、中文讲稿”或“沿用上传的导师模板”。页数与时长是制作约束，具体信息取舍仍需保持方法和证据完整。常用请求见 [使用指南](usage.md)。

## audit 报讲稿不一致

确认检查的是最终 PPTX 和最终讲稿。Markdown 每个 `##` 标题对应一页，标题下面只放本页口播；页数和顺序须与 PPTX 一致。匹配忽略空白，其他字符应一致。也可传入按页排序的字符串数组 JSON：`--expected-notes notes.json`，不能同时使用 `--script`。

## 检查通过是否意味着 PPT 可以直接汇报

还需要原文核对与最终 PPTX 的逐页视觉验收。结构检查能发现备注缺失等问题，科学结论、公式含义、箭头关系和图表可读性需要进一步核对，见 [质量标准](quality.md)。
