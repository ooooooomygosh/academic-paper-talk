# 版式与讲稿

## 视觉系统

保留参考 `assets/reference.pptx`，以及本包所配示例渲染。开始排版前实际查看[总体流程](../assets/examples/overall-flow.png)、[模块展开](../assets/examples/module-detail.png)、[基线协议](../assets/examples/baseline-protocol.png)和[实验讲解](../assets/examples/experiment-explanation.png)，不要仅凭文字猜风格。参考为 16:9，13⅓ × 7½ inch（1280 × 720 CSS px），正文左对齐，左右留白约 5%。

| 用途 | 参考色 |
| --- | --- |
| 画布 | #FFFFFF |
| 正文与主要标题 | #172D3B |
| 重点与模块 | #1C7395 |
| 少量关键结论 | #13838C |
| 来源与辅助文字 | #5E6B75 |
| 细分隔线 | #D0DEE5 |
| 表头或技术模块淡底 | #EDF4F7 |

优先沿用参考的 Noto Sans CJK SC；运行环境没有时用已确认可用的中文字体，如 PingFang SC。不要仅因字体名字熟悉就假设存在。常规标题约 30–34 pt、正文约 18–22 pt、来源约 11–13 pt；具体继承参考层级并检查长中文与英文混排。正文缩小之前先拆页、删重复、缩短句子。避免把 96 DPI 的 px 直接当 pt。

原图的颜色保留。技术方框只表示真实模块，不做装饰卡片。整体留白、平面对齐，不加渐变、阴影、徽章、无关照片、章节过场或机械“谢谢”页。封面只放可核验书目信息和准确的一句话任务；用户明确要首页题名截图时按要求保留。

## 常用页面形式

- Spark：一个明确观察配原图、对应表或具体失败示例。
- 系统或时间线：标出观测、控制、隐藏状态和决策时刻。
- 总体流程：一条主数据流，加实际侧输入／反馈，模块编号在后续页保持一致。
- 模块页：原文内部图或简化原生图，加输入／处理／输出及一条关键式子；明确展开总体图哪一步。
- 算法示例：沿同一实例展示更新前、一次操作和更新后，原图足够清楚时直接用原图。
- 协议与 baseline：普通原生表格，不把长段落塞进小格子。信息来源或预算不同直接列明。
- 实验页：可读的原图占主要空间，旁边只放读图必需的解释、主要观察和条件。
- 研究问题：具体假设、机制与下一项验证，使用普通文字、表格或必要示意。

标题可以是清楚的主题，也可以是证据支持的发现。避免每页长句标题、反复“赋能／范式／闭环”等空词。科学上的闭环必须画出反馈和更新，不能只用这个词。

## 原图与可编辑性

从 PDF 提取或高分辨率裁剪，保留坐标、单位、legend、subplot 标签和需要引用的图号。去掉无关正文，不截断曲线端点。用户明确要求保留完整图时不擅自拆分。关键图太密就拆成可读子图或专页，不拉伸改变比例。

流程、表格和自行整理的解释保持原生对象。原始实验曲线可使用论文图，不为“可编辑”虚构采样点重绘。已有原图解释清楚时无需重画；新增可编辑示意服务于输入输出、时序和模块关系。自己的示意与论文原图区分标注。

## 备注的写法

先解释本页在整条论证中的位置，再沿视觉顺序讲内容，最后自然连接下一页。可说“先看左边的当前观测”，这是能读出来的指图口播；不可写“此处停顿十秒”“指向右图讲解”等给讲者的操作提示。

模块页口播要说明变量怎么进入、怎样变化、为何必要和怎样传给下游。实验页口播要说明每根轴和曲线、具体比较、观察、原因及结论范围。不能只是把 bullet 加上“首先／其次／最后”。

不设统一字数配额：封面可短，复杂图需要更长解释。若完整讲稿使时间明显超出计划，应重排正文与附录或减少重复，不能靠删除关键方法来满足页数。自己试读核对时长，不在实际备注内写时长标记。

来源放页脚／附录。一般格式为“作者，年份，PDF pX，Fig. Y／Eq. Z”；完整题名、版本、DOI 可集中在封面或来源附录。证据适用条件跟相应结果放在一起，不用重复免责声明淹没正文。

## 模块页口播示例

以下只示范讲法，不是其他论文事实：

“这一页先看完整流程。当前观测先经过初步映射，得到与历史表示尺寸一致的特征。历史信息在中间的融合模块接入，因此第一步并没有使用历史。融合后的特征再经细化模块输出当前估计。下一页展开的是初步映射和细化所共用的模块形式，中间怎样利用历史会在后面单独解释。”

关键是解释连接与作用。实际论文是否共享参数、尺寸是否一致、历史在哪接入，都必须重新核对，不能照抄例子。
