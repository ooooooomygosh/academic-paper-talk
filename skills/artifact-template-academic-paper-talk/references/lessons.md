# 实际经验与修正

这些经验来自 Coded Beam Training 的 Spark 汇报、Channel Deduction 修订，以及四篇独立精读 PPT。案例用于校准解释与核验方法，新的论文必须重新读取原文。

| 曾出现的问题 | 为什么不够 | 固化的处理方式 |
| --- | --- | --- |
| 用 Transformer、卷积码、GP 等名词代表方法 | 听众不知道一次操作怎样发生 | 用一个输入走完测量、计算、保存状态、下一步与停止 |
| LLR 被解释成 0101 | 丢失软信息的实数大小，以及它如何参与累计代价 | 解释变量类型、符号和幅值，展示候选评分与更新；硬判结果另行说明 |
| 只画编码结构，却不解释怎么扫描 | 离线给全部方向编码与在线发射的关系不明 | 指明矩阵行列语义、每次一支赋形向量的覆盖与 UE 返回量 |
| 把前人的工作写成笼统的特定方案 | 错把已有编码或自适应称为新贡献 | 核对最接近原文，区分 baseline 摘取与原作完整能力 |
| Fig. 3 与 Fig. 4 混在同页 | 总体流程与内部结构层级不明 | 总流程先行，模块页明确展开总图的编号与接口 |
| 备注含提示、时长、来源和问答 | 用户读出来无法成为正常汇报 | 备注仅保留完整口播，出处去页脚／附录，问答按需单独给 |
| 重要公式只藏在备注 | 听众看不见方法依据 | 正文保留关键公式、变量和作用，长推导放附录 |
| 只说主结果更好 | 无法知道差距来自哪里 | 先列 baseline 的输入、预算、硬件和信息，再按 claim 选择实验 |
| 四篇初稿都出现过流程箭头反向 | 创建接口的端点名与直觉不一致 | 做 A→B smoke render，并逐条查看导出的成品箭头 |
| 原图坐标标签或图号被裁掉 | 核验和读图所需信息丢失 | 查看高分辨率 crop 的四边，成品中再次检查 |
| 长标题、英文换行、密集表格溢出 | 代码边界不等于实际文字与行高 | 改内容和空间，最终文件重新渲染；不要只缩字体 |

## 四篇论文带来的核验提醒

- Near-Optimal NFBT：复接收信号 posterior 与功率／速率目标要分开；数学保证中的变量与目标不可自动泛化。固定核项与自适应观测集合更新的费用分别说明。
- Distance-Dependent Beam Split：距离环 α 与实际距离 r 不等同；宽带 pilot 与标量观测数量不等同；覆盖演示和主实验 K 可能不同。图的 SNR 范围与正文有出入时具体处理。
- AMBER：重新读 Fig. 2 和 Remark 后，发现 training-only 不止 CMA，还包括 modality-specific Transformer。不能沿用旧阅读卡的不完整概括。当前 GPS 与历史 beam 的时间边界需分别核对，RCE 的组合消融不能单独归给 CMA。
- ChannelLM：PL 与 pilot-conditioned CSI 是不同路径，环境编码、感知定位与 RF 标签来源要分开。增强后的样本数不等于原始场景数；分支参数量不等于全系统参数量；原文未披露是否冻结时不补造训练细节。

## 不固化的旧习惯

不把某次 8 页、23 页、固定备注字数、特定天线数或数据集写成通用要求。早期备注中的“讲解／追问／出处”分区已被本用户明确的“直接朗读”偏好覆盖。普通组会 skill 的黑白导师模板与本 skill 的白底深蓝参考是两个不同用途，不能混称严格同一模板。
