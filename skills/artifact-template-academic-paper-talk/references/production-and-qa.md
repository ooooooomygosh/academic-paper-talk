# 制作与验收

## 当前工具与文件

通过当次会话的技能目录找到 Presentations，读取 implementation、API quick start、template following 和 finalization。调用 workspace dependency loader，使用返回的 Node、Python、包和 override binaries。不要硬编码某次插件版本或临时目录；不要修改系统 HOME／CODEX_HOME。

当前本地制作路线使用 JavaScript ES modules 与 `@oai/artifact-tool`，不用 python-pptx。实际未来版本以当前技能要求为准。渲染工具需要 runtime 环境变量时按其文档完整设置；Python 包不存在时使用可用的 PDF 工具，不把装包或猜路径当作第一步。

在任务目录的 `work/` 留大纲、中间稿、图像、来源映射与验证记录；`outputs/` 只放成品。按当前 skill 执行 authoring marker 和 finalization。最终文件先在本任务内验证，再原样复制到用户指定目录，核对 hash；源论文和模板只读。

## 先验证代表性页面

复杂 deck 可以先做一页流程、一页表格和一页原图实验，检查字体、边距、公式和箭头，再展开全套。做完不能停在这三页。参考已提供风格，不需要再要求用户选择模板。

Native connector 的 head／tail 命名不能凭直觉判断：已发生过代码坐标从左到右，而导出箭头实际指向左方。用简单 A→B 导出并渲染验证当前 API 的端点语义。成品再核对反馈支路、折线方向、交叉位置和落点；不要永久硬编码某次 API 的 head／tail 修补。

表格实际高度会受字号、行距、cell padding 和自动换行影响。检查导出后对象尺寸与页脚间距，密集表格尤其要看最后一行；不要只相信创建时的 height。中文字体、公式负号、上下标和希腊字母都需视觉检查。

## 事实验收

- 所有主结论能回到原文位置；来源版本与截图一致。
- 变量、维度、时点、共享参数、训练与在线支路均能前后对应。
- 理论保证对象与实验指标不混同；有条件的保证没有扩大成任意场景最优。
- 最重要的性能数值保留 baseline、预算、分母、单位和实验范围。
- 原文直接结论、机制解释、自己的推导、教学示例、研究设想身份清楚。
- 用户的研究上下文没有被虚构；没有把“未报告”自动写成“存在问题”。

## 完整性与结构检查

检查最终 PPTX 而非仅构建代码：页序、页数、每页备注、原生表格、流程连接对象、占位符残留、来源位置。每页必须有完整备注，包括封面和附录；备注与独立讲稿保持一致。可使用本 skill 的纯标准库辅助脚本：

```text
python scripts/audit_pptx.py <final.pptx> --script <逐页朗读稿.md> --out <work/audit.json>
```

脚本路径相对本 skill；运行时传入实际绝对路径。朗读稿采用一个 `## 第 N 页 标题` 对应一页，其后正文即该页备注。需要更可靠地核对时可用 `--expected-notes <notes.json>`，JSON 必须是按页排列的字符串数组。可以加 `--require-native-tables` 和 `--require-native-diagrams` 检查是否至少存在相应对象；它不能证明所有指定对象都可编辑。

脚本检查缺失／空备注、讲稿不同步、典型提示标签和对象计数，返回非零表示应修复的结构问题。它不验证论文事实、科学图箭头含义、文本溢出或真实可读性。短备注仅提示复核，不能用字数代替口播质量判断。

## 最终视觉检查

从最终交付 PPTX 重新渲染，逐页打开检查，不只看 montage：

1. 标题、正文、来源、页码没有相互覆盖或越界。
2. 原图坐标、legend、子图编号和关键曲线可读，没有被裁切。
3. 流程箭头方向正确，支路进入正确模块，标签没有挡住连接。
4. 表格行高足够，最后一行与页脚分离，数字和单位不被换行拆坏。
5. 字体和符号正常，公式分式、下标、负号和粗体显示正确。
6. 源图没有变形，教学图与论文实证没有混淆。
7. 风格保持克制，没有残留另一篇论文的题名、数字或模块。

结构检查通过只表示结构项通过。记录实际查看的页和修正，不虚构“已在 PowerPoint 打开”；若只用渲染器就如实称渲染检查。版本修订后重新核查变化页和受影响的相邻页，最终整体扫描页序和内容完整性。

## 交付

PPTX 与逐页朗读稿／大纲是默认交付。需 PDF 时额外导出并查看其实际排版，不把普通 slides PDF 说成包含 speaker notes。只报告影响使用的限制；内部验证、源代码和多份候选不占用户交付列表。
